# 四季已知片源固定裁切

已对本机四季 **260份完整原片** 完成源SHA扫描、全部首尾边界图复核，以及逐集无损复制边界窗口的实际验证。固定清单为 `config/cuts/four-seasons-known-v1.json`。正常使用只按季和集数读取已定切点，**不再逐集找时间、不再运行模板识别、不需改参数**。特殊情况也已经逐集写入清单。

- 第四季E25–E46为室内录制：从坐定现场开始，保留最后动作；源片没有剧场入场和结束远景，不能套出并不存在的镜头。

这些都是清单内的已知情况，运行时无需人工再决定。只有源文件换版本、哈希不同、已存输出或策略发生不匹配时才拒绝沿用旧切点，并保留原文件。

## 直接使用

在仓库执行，例如裁第三季第20集：

```powershell
pwsh scripts/qqw.ps1 -Command cut-known -CutSeason S03 -Episode 20
```

输出到数据根目录的 `videos/S03E20.mp4`。其他季、集数只改 `-CutSeason` / `-Episode`；一次明确选择一集，不隐式重切全库。默认使用现有D盘四季目录；需要其他位置时用现成的 `-SourceDir` 和 `-RootDir`。

也可直接运行 `python scripts/cut/cut_known.py --source <原片> --output <新裁片.mp4>`。常规裁切只需要现有Python、FFmpeg、FFprobe和仓库清单，不需要OpenCV、Pillow或那些本地审看片目录。完整源SHA匹配后才允许使用；实际首帧解码哈希、编码/尺寸/轨道、尾部包边界和首尾各2秒AV解码均检查。匹配known/cut收据的已有输出可核对完整SHA后复用；未知已有媒体拒绝覆盖。失败保留partial和证据。

原S01 `cut` 命令、既有已确认裁片和生产项目季号未改。新季只完成了初切准入；不会自动启动OCR、Mask、上传或云端后处理。

## 开发与重新建库

已知源不需要重建。`build_known_cuts.py`负责扫描候选，依赖OpenCV/NumPy/Pillow；`freeze_known_cuts.py`要求四季完整、每份扫描SHA和实际审看图SHA匹配的复核记录才发布，扫描器不会自批。`verify_known_boundaries.py`对冻结结果实际复制和解码首尾窗口。`season_cut.py inspect → plan → cut`保留为异常版本的开发审看入口；它不是已知库的日常操作要求。
