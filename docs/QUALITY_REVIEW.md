# 画面增强收益的实际对照

## E49：2026-10-28复查

用户认为静态画质提升不明显，补帧观感较好。Windows实际取回同一新母片留存的60、1700、2800秒原始PNG，与已回传最终片相同时刻的解码帧比较。这三个时刻同时落在25fps和60fps原始帧网格，画面姿态一致；裁切排除新增ASS，双侧采用完全相同裁切和2倍最近邻显示。原母片已按生命周期释放，留存PNG不等于可重新完整检查母片。

实际逐组查看后的判断：静态收益轻微，部分脸部轮廓、发际边缘和衣服条纹略收敛，皮肤更平滑；未见足以称为显著升级的眼睛、头发或皮肤真实细节恢复。远景的小脸依然模糊。正常播放中不易察觉增强，符合这些样本的结果，不能用“模型确实运行过”替代可见质量收益。

对照是母片PNG与最终交付编码，差异也包含最终编码、色彩转换等影响；像素差仅表示变化，不是质量分数。三组静帧不能代表每帧，也不能据此量化补帧收益或估算关闭恢复能节省多少时间。总生产耗时含补帧、编码、检查和资源等待，不能全部算作超分耗时。

本次仅记录质量评估，不据此自动改生产参数、关闭恢复或重跑E49。后续如决定调整，应先比较短片的原画、现有温和恢复和候选方案，以实际可见收益与耗时取舍。

## 复现

实际媒体、PNG、对照图和哈希清单保留在数据根目录，不提交Git。`scripts/compare_frame_pairs.py`读取同一目录的`source_60.png`/`final_60.png`等输入，生成等倍率对照和输入/输出SHA清单。例如：

```powershell
python scripts/compare_frame_pairs.py --directory D:/qingqingwu/work/S01E49/quality-comparison --sample 60,820,140,360,540 --sample 1700,800,340,360,360 --sample 2800,870,190,360,540
```

成片帧提取使用FFmpeg的同一时间基准，例如`-ss 60 -i <成片> -frames:v 1 -vf format=rgb24`。对照前必须核实时间与姿态；不可拿不同镜头、缩放尺寸或不同锐化设置的播放器截图混比。输出已存在时脚本拒绝覆盖，重做应使用新的比较目录。

## 快速候选实验：2026-10-28

用户倾向可见收益与速度，接受不影响整体的细节猜测。本次只是候选研究，不代表批准更改生产参数或重跑E49。

新增 `scripts/preview_fast_filters.py`，对留存母片PNG生成轻量滤镜候选，并对现有成片做有界测速。CAS方案为亮度锐化加少量对比度/饱和度；加强方案额外加入宽半径轻量unsharp。实际查看60和1700秒相同裁切：轮廓更利落、衣服纹理更突出，但小脸五官没有明显恢复，也会强调噪声；不能宣称画质质变。候选图须使用 compare_frame_pairs.py 的 --after-label 明确标注候选，不能标成已交付成片。

同一20秒视频、CPU四线程、降至25fps后解码及滤镜输出到null的单次测速：

| 环境 | 无增强基线 | CAS方案 | 加强方案 |
| --- | ---: | ---: | ---: |
| Windows | 3.063秒 | 3.900秒 | 5.961秒 |
| Linux服务器 | 6.586秒 | 10.141秒 | 15.569秒 |

这仅是短片CPU解码、色彩转换和滤镜吞吐，不含RIFE、音频、编码、落盘与全片校验，不可当作整集ETA。报告与媒体保留在数据目录 work/S01E49/fast-look-preview 和服务器 post/reports/fast_filters_20261028，不提交Git。
